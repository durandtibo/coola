    coola.utils.bloom_filter ¶

    Contain the implementation of a Bloom filter.

    coola.utils.bloom_filter.BloomFilter ¶

    Fixed-memory approximate set-membership structure.

    A Bloom filter answers "have I probably seen this item before?" using a fixed amount of memory. It guarantees no false negatives (an item that was added is always reported as present), at the cost of a tunable false-positive rate (an item that was never added may occasionally be reported as present). Memory usage is fixed up front based on the expected number of items and the desired false-positive rate, regardless of how many items are actually added. It is a standalone utility, typically used for approximate duplicate detection over large streams of items.

    Warning

    The filter is not thread-safe: concurrent add or add_and_check calls can lose bits. Protect it with a lock if it is shared between threads.

    Example 
    >>> from coola.utils.bloom_filter import BloomFilter
>>> bf = BloomFilter(expected_items=1000, fp_rate=0.01)
>>> bf.add_and_check(b"hello")
False
>>> bf.add_and_check(b"hello")
True
>>> b"hello" in bf
True
>>> b"world" in bf
False

    coola.utils.env_vars.temp_env_vars ¶

    temp_env_vars(env_vars: dict[str, Any]) -> Generator[None]

    Context manager to temporarily set or modify environment variables.

    Changes are automatically reverted when exiting the context, even if an exception occurs. If a variable already exists, its original value is saved and restored on exit. If a variable doesn't exist, it is created temporarily and removed on exit. All operations are guaranteed to execute via try/finally, even if an exception is raised inside the with block.

    Note

    This context manager mutates os.environ, which is process-wide: it is not thread-safe.

    Parameters:

    Name Type Description Default
    env_vars dict[str, Any]

    The environment variables to set, as a mapping of variable name to value. Values are automatically converted to strings.

    		 required
    Example 
    >>> import os
>>> from coola.utils.env_vars import temp_env_vars
>>> # Temporarily override an existing variable
>>> os.environ["MY_HOME"] = "/original/home"
>>> with temp_env_vars({"MY_HOME": "/tmp/home"}):
...     print(os.environ["MY_HOME"])
...
/tmp/home
>>> print(os.environ["MY_HOME"])
/original/home
>>> # Temporarily create new variables
>>> with temp_env_vars({"TEMP_API_KEY": "secret123", "TEMP_DEBUG": "true"}):
...     print(os.environ["TEMP_API_KEY"])
...     print(os.environ["TEMP_DEBUG"])
...
secret123
true
>>> print(os.environ.get("TEMP_API_KEY"))

    Note

    Changes to os.environ affect the entire Python process, not just the current thread. Use with caution in multi-threaded applications.

    coola.utils.fork ¶

    Reset the state of the objects in a forked process.

    A process created with os.fork (e.g. a worker of a pre-fork server, a torch.utils.data.DataLoader worker or multiprocessing with the fork start method) starts with a copy of the memory of its parent, but only with the thread that forked. Two kinds of state need a reset in the child process:

    • the state of the identifier generators: without a reset, the parent and its children would produce the same random values and the same counters, so they could produce the same identifiers;
    • the locks: a lock that another thread of the parent held at the time of the fork stays locked forever in the child, because the owner does not exist there.

    The objects that register with track_fork are reset in the child process right after the fork.

    coola.utils.lru.LRUCache ¶

    Bases: Generic[K, V]

    A bounded, dict-like cache that evicts the least-recently-used entry once it grows past maxsize.

    Both reading (__getitem__/get) and writing (__setitem__) an existing key mark it as most-recently-used. The class supports the common dict-like operations (__contains__, __len__, __iter__, __delitem__, keys/values/items, clear, pop) needed to act as a drop-in cache store.

    coola.utils.singleton ¶

    Define a thread-safe lazy singleton helper.

    Several modules expose a get_default_registry() function that builds and caches a registry on first use. Building it eagerly at import time is not an option here because some registries are constructed via imports that are deliberately deferred to avoid circular imports between coola.equality and coola.registry.
