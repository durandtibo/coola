    Hashing

    coola.hashing ¶

    Provide deterministic hashing functions.

    These are content hashes for identity and caching, not for security: do not use them for passwords, signatures or integrity against an attacker.

    Hashes are deterministic across calls, processes and machines, and follow these rules:

    • Every hash is domain-separated by a type tag, so values of different types never share a hash even if their text form is the same (1, 1.0, True and "1" are all distinct).
    • Ordered containers (list, tuple, OrderedDict) are order-sensitive and unordered containers (dict, set) are not, like in coola equality. Each container family has its own tag, so a list and a tuple with the same items hash differently.
    • Container hashes are built only from the hashes of their children, resolved through a HasherRegistry.
    • Unsupported types raise TypeNotRegisteredError (a KeyError) unless ignore_unhashable is set.
    • A container that contains itself raises ValueError.
    • The output is a lowercase hex string of length characters (an even number from 2 to 128, default 64).

    coola.hashing.BaseHasher ¶

    Bases: ABC, Generic[T]

    Base class for type-specific hashers.

    A hasher describes the content of a type, it does not hash. The rules of the contract are:

    1. encode is pure and cheap: it does not call the registry, does not recurse, does not modify data and does not depend on id(), on hash() or on the iteration order of a set or of a mapping (an unordered Node says so instead).
    2. It returns bytes (a leaf, see tagged) or a Node.
    3. The children of a Node are encoded by their own hasher.
    4. The tag is a constant of the hasher, except for the user-defined classes whose qualified name is the identity. A subclass therefore hashes like its base.
    5. An exception propagates unchanged.
    Example 
    >>> from coola.hashing import BaseHasher, Node, hash_object, register_hashers
>>> class Point:
...     def __init__(self, x, y):
...         self.x, self.y = x, y
...
>>> class PointHasher(BaseHasher[Point]):
...     def encode(self, data):
...         return Node("Point", [data.x, data.y])
...
>>> register_hashers({Point: PointHasher()})
>>> hash_object(Point(1, 2)) == hash_object(Point(1, 2))
True
>>> hash_object(Point(1, 2)) == hash_object(Point(2, 1))
False

    coola.hashing.ContentHasher ¶

    Bases: InlineDisplayMixin, BaseHasher[SupportsCoolaHash]

    Hasher for objects that implement __coola_hash__.

    The object is described by the tag custom:module.Class and the value of __coola_hash__, which the engine hashes through the registry. The qualified class name is part of the tag, so two classes with the same content hash differently. The default registry uses it as a fallback for every class that defines the method and has no hasher of its own.

    Example 
    >>> from coola.hashing import ContentHasher, hash_object
>>> class Point:
...     def __init__(self, x, y):
...         self.x, self.y = x, y
...     def __coola_hash__(self):
...         return (self.x, self.y)
...
>>> hasher = ContentHasher()
>>> hasher
ContentHasher()
>>> hasher.encode(Point(1, 2)).children
[(1, 2)]
>>> hash_object(Point(1, 2)) == hash_object(Point(1, 2))
True

    coola.hashing.DataclassHasher ¶

    Bases: InlineDisplayMixin, BaseHasher[Any]

    Hasher for dataclass instances.

    The hash combines the qualified class name with a mapping from field name to field value, with every value hashed through the registry. Only the fields with compare=True are hashed, like in objects_are_equal, so two equal dataclasses have the same hash. Because dataclasses have no common base class, it cannot be registered for a type: the default registry uses it as a fallback (see HasherRegistry.register_fallback) for every dataclass that has no hasher of its own.

    Example 
    >>> from dataclasses import dataclass
>>> from coola.hashing import DataclassHasher
>>> @dataclass
... class Point:
...     x: int
...     y: int
...
>>> hasher = DataclassHasher()
>>> hasher
DataclassHasher()
>>> hasher.encode(Point(1, 2)).ordered
False

    coola.hashing.DatetimeHasher ¶

    Bases: InlineDisplayMixin, BaseHasher[date | time]

    Hasher for datetime.date, datetime.datetime and datetime.time objects.

    This hasher converts the object to its ISO 8601 string representation via isoformat() and hashes that string under a tag made of the concrete class name.

    Since datetime.datetime is a subclass of datetime.date, both types are handled by this hasher. The class name is part of the tag, so a date and a datetime never produce the same hash, even for the same calendar day.

    Aware datetimes are converted to UTC first, so equal instants in different time zones hash the same, like they compare equal. Naive and aware datetimes differ. An aware time is normalised the same way, like time.__eq__ does: the offset is subtracted from the time of day (without wrapping around midnight) and the payload is the resulting number of microseconds. A naive time uses its ISO string.

    Example 
    >>> from datetime import date
>>> from coola.hashing import DatetimeHasher
>>> hasher = DatetimeHasher()
>>> hasher
DatetimeHasher()
>>> hasher.encode(date(2021, 1, 1))
b'date\x002021-01-01'

    coola.hashing.EnumHasher ¶

    Bases: InlineDisplayMixin, BaseHasher[Enum]

    Hasher for enum.Enum members.

    The hash depends on the qualified class name and the member name, not on the member value. IntEnum and StrEnum members are therefore not collapsed into int and str.

    Example 
    >>> from enum import Enum
>>> from coola.hashing import EnumHasher
>>> class Color(Enum):
...     RED = 1
...
>>> hasher = EnumHasher()
>>> hasher
EnumHasher()
>>> hasher.encode(Color.RED).startswith(b"Enum")
True

    coola.hashing.HasherRegistry ¶

    Bases: TypeRegistry[Hasher[Any]]

    Registry that manages and dispatches hashers based on data type.

    This registry maintains a mapping from Python types to hasher instances and uses the Method Resolution Order (MRO) for type lookup. When hashing data, it automatically selects the most specific registered hasher for the data's type, falling back to parent types or a default hasher if needed.

    Parameters:

    Name Type Description Default
    initial_state dict[type, T] | None

    Optional initial mapping of types to hashers. If provided, the state is copied to prevent external mutations.

    		 None
    Example

    Basic usage with a sequence hasher:

    >>> from coola.hashing import HasherRegistry, SequenceHasher, StrHasher
>>> registry = HasherRegistry({object: StrHasher(), list: SequenceHasher()})
>>> registry
HasherRegistry(
  (<class 'object'>): StrHasher()
  (<class 'list'>): SequenceHasher(tag='sequence')
)
>>> len(registry.hash([1, 2, 3]))
64

    Registering custom hashers:

    >>> from coola.hashing import HasherRegistry, SequenceHasher, StrHasher
>>> registry = HasherRegistry({object: StrHasher()})
>>> registry.register(list, SequenceHasher())
>>> len(registry.hash([1, 2, 3]))
64

    Working with nested structures:

    >>> from coola.hashing import get_default_registry
>>> registry = get_default_registry()
>>> data = {"a": [1, 2], "b": [3, 4]}
>>> len(registry.hash(data))
64

    coola.hashing.HasherRegistry.hash ¶

    hash(
    data: object,
    *,
    length: int = 64,
    ignore_unhashable: bool = False,
) -> str

    Hash the given data.

    This is the registry-level entry point for hashing. It finds the hasher of each object with find_hasher and walks the nested structure with the engine (see coola.hashing.engine). The hash is the first length characters of the 128-character hex digest, so a hash is the start of the longer ones.

    Parameters:

    Name Type Description Default
    data object

    The data to hash. Can be a nested structure such as a list, dict, or tuple.

    		 required
    length int

    The length of the returned hex string: an even int between 2 and 128 inclusive.

    		 64
    ignore_unhashable bool

    If True, objects for which no hasher is registered (including their parent types via MRO) are replaced by a deterministic placeholder hash instead of raising a TypeNotRegisteredError. This also applies to nested objects. The placeholder only depends on the type, so any two unsupported objects of the same type hash the same; a UserWarning is emitted once per type. Defaults to False, which raises an error.

    		 False

    Returns:

    Type Description
    str

    A string representing the hash of the input data.

    Raises:

    Type Description
    TypeNotRegisteredError

    If no hasher is registered for the type of data or of a nested object (or any of their parent types) and ignore_unhashable is False. It is a subclass of KeyError.
    ValueError

    If length is not valid, or if data contains itself (a self-referencing container).
    Example 
    >>> from coola.hashing import get_default_registry
>>> registry = get_default_registry()
>>> len(registry.hash({"scores": [95, 87, 92], "name": "test"}))
64

    coola.hashing.MappingHasher ¶

    Bases: InlineDisplayMixin, BaseHasher[Mapping[Any, Any]]

    Hasher for mapping types.

    This hasher describes a mapping as a Node whose children are the keys and the values, which the engine hashes through the registry. The entries (a key and its value) are sorted by digest, not by key, so mappings with the same key-value pairs but different insertion orders produce the same hash, without requiring keys to be orderable. This matches coola equality, which ignores the order of the keys of a dict. Register the hasher with ordered=True for a mapping type whose order is meaningful, like OrderedDict: its equality is order-sensitive too.

    The tag identifies the mapping family, so a dict and an OrderedDict with the same items hash differently.

    Parameters:

    Name Type Description Default
    tag str

    The type tag mixed into the hash. Defaults to "mapping".

    		 'mapping'
    ordered bool

    If True, items are hashed in iteration order instead of being sorted. Defaults to False.

    		 False
    Example 
    >>> from coola.hashing import MappingHasher
>>> hasher = MappingHasher()
>>> hasher
MappingHasher(tag='mapping', ordered=False)
>>> hasher.encode({"a": 1}).tag
'mapping'

    coola.hashing.NumpyArrayHasher ¶

    Bases: InlineDisplayMixin, BaseHasher['np.ndarray']

    Hasher for numpy.ndarray objects.

    The hash depends on the dtype (with its byte order), the shape and the values, not on the memory layout: a non-contiguous view hashes like its contiguous copy. -0.0 hashes like 0.0, like in the equality.     coola.hashing.PathHasher ¶

    Bases: InlineDisplayMixin, BaseHasher[PurePath]

    Hasher for pathlib.PurePath and pathlib.Path objects.

    coola.hashing.ReprHasher ¶

    Bases: InlineDisplayMixin, BaseHasher[Any]

    Hasher for objects whose repr() is a reliable canonical representation.

    This hasher converts the object to its repr() string and hashes it under a type tag.     coola.hashing.SecretHasher ¶

    Bases: InlineDisplayMixin, BaseHasher['SecretStr | SecretBytes']

    Hasher for SecretStr and SecretBytes values.

    A secret is a value with a hasher, so the policy is the one of the registry and applies wherever the secret is (in a model, a dict, a list, a dataclass...).

    Parameters:

    Name Type Description Default
    on_secret Literal['reveal', 'exclude', 'error']

    What to do with a secret:

    • "error": raise a ValueError. The message never contains the secret. It forces an explicit decision instead of hashing, or silently ignoring, secret data by accident.

    • "exclude": hash a constant, so the value is never hashed and two objects that differ only by a secret have the same hash. The position of the secret is kept: it is part of the schema of the class.

    Defaults to "error".

    		 _ERROR

    Raises:

    Type Description
    ValueError

    coola.hashing.hash_object ¶

    hash_object(
    data: object,
    *,
    registry: HasherRegistry | None = None,
    length: int = 64,
    ignore_unhashable: bool = False,
) -> str

    Compute a hash of a nested data structure.

    The hash is deterministic and depends on the type of every value, on the order of ordered containers, and not on the order of unordered ones. For example [1, 2], (1, 2) and {1, 2} all hash differently, while {"a": 1, "b": 2} and {"b": 2, "a": 1} hash the same. An OrderedDict is the exception among mappings: the order of its keys matters, so two OrderedDict with the same items in a different order hash differently.

    Note

    The hash of a dataclass, a pydantic model, an enum member or an object with a __coola_hash__ method includes the module and the qualified name of its class. The hash changes when the class is renamed or moved to another module, and a class defined in a script run as __main__ hashes differently from the same class imported. Do not persist these hashes (or the IDs derived from them, such as generate_stable_uuid5) across such a change.

    The options are keyword-only: it was easy to write hash_object(data, 32) and pass 32 as the registry.

    Parameters:

    Name Type Description Default
    data object

    The data to hash. Can be a nested structure such as a list, dict, or tuple.

    		 required
    registry HasherRegistry | None

    The registry used to resolve hashers for each data type. If None, the default registry is used.

    		 None
    length int

    The desired length of the returned hex string. Must be an even number between 2 and 128 inclusive. Defaults to 64.

    		 64
    ignore_unhashable bool

    If True, objects for which no hasher is registered (including nested objects found while hashing sequences or mappings) are replaced by a deterministic placeholder hash instead of raising an error. The placeholder only depends on the type, so it is lossy, and a UserWarning is emitted each time one is used. Defaults to False, which raises a TypeNotRegisteredError (a KeyError) when an unhashable object is encountered.

    		 False

    Returns:

    Type Description
    str

    A string representing the hash of the input data.

    Raises:

    Type Description
    TypeNotRegisteredError

    If data (or a nested object within it) has a type for which no hasher is registered and ignore_unhashable is False. It is a subclass of KeyError.
    TypeError

    If length is not an int (bool is rejected too).
    ValueError

    If length is not an even number between 2 and 128, or if data contains itself (a self-referencing container).
    Example 
    >>> from coola.hashing import hash_object
>>> len(hash_object({"a": 1, "b": "abc"}))
64
>>> len(hash_object({"a": 1, "b": "abc"}, length=16))
16
