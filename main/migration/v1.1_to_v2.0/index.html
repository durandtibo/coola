    Migration Guide: v1.1 to v2.0¶

    This guide explains how to migrate your code from coola version 1.1.x to version 2.0.x.

    Version 2.0 is a large release. Most code that only calls objects_are_equal, hash_object or summarize keeps working, but the results of some calls change (hashes, summaries, a few comparisons). Code that extends coola (custom testers, hashers, summarizers, transformers, child finders, loaders or registries) must be ported.

    How to use this guide¶

    1. Read Before you start and check the requirements.
    2. Go through the checklist and keep the items that match what you use.
    3. Open the section of each item: every section starts with who is affected, then lists the changes in a table (Before / After) and shows a code example when a port is needed.

    At a glance¶

    Area Main change Section
    Python and extras Python 3.11 or later; new scipy and testing extras 1
    Exceptions AlreadyRegisteredError, MissingPackageError and MaxDepthExceededError replace RuntimeError / RecursionError 2
    coola.registry One storage class (Registry) and one dispatch class (TypeRegistry), fallbacks, pickling 3
    coola.equality One engine; a tester returns a verdict or child pairs; compare replaces show_difference 4
    coola.hashing One engine and encode; every hash changes 5
    coola.summary One engine, one option object (SummaryConfig); new layout 6
    coola.recursive Transformers implement expand; the engine recurses 7
    coola.iterator One child finder (find_children) for dfs_iterate and bfs_iterate 8
    coola.factory Strict contracts: one way to import, call and check a target 9
    coola.random One seed domain, a strict set_rng_state, one registry 10
    coola.reducer BaseReducer owns the checks; strict input 11
    coola.nested Built on the engines; keyword-only options; stricter conversions 12
    coola.utils Leaf layer: formatting and registry helpers moved; import helpers replaced 13
    coola.display, coola.testing Optional rich; marks and fixtures modules 14, 15
    coola.io, coola.identifier, coola.rounding, coola.validation New packages (nothing to migrate from the release 1.1.10) 16 to 19

    Before you start¶

    Requirements. coola 2.0 requires Python 3.11 or later (section 1).

    Baseline. The baseline is the release 1.1.10. Some tables also compare with states of the development branch between 1.1.10 and 2.0, so a "Before" cell can name something the release never had. If you only used the release 1.1.10, skip these parts:

    • The packages coola.io (section 16), coola.identifier (17), coola.rounding (18), coola.validation (19), coola.formatting and coola.display.rich did not exist. They are new (see section 20).
    • These names were not in 1.1.10: DataclassMarker, BaseTypeDispatchRegistry, resolve_or, register_fallback, register_lazy, enter_dataclasses, SupportsHash, HashableHasher, _allowed_prefixes_, is_object_config, get_random_seed, LazySingleton, add_prefix_suffix_to_keys, coola.testing.registries, coola.testing.marks.requires and plural=, smallest_items and int_repr.

    The rows that name a class, a function or an argument of 1.1.10 are the ones to apply.

    Migration checklist¶

    Everyone¶

    • [ ] Use Python 3.11 or later (section 1).
    • [ ] Regenerate every stored hash and stable identifier: the hash format changed (section 5).
    • [ ] Pass the options of objects_are_equal, hash_object, recursive_apply, random_seed, dfs_iterate, bfs_iterate and the register_* functions by keyword (sections 3 to 10).
    • [ ] Replace show_difference=True by compare(...) or assert_objects_equal(...) (section 4).
    • [ ] Catch AlreadyRegisteredError, MaxDepthExceededError and MissingPackageError instead of RuntimeError / RecursionError, and do not rely on max_depth=1000 (section 2).
    • [ ] Read the new summary layout if you compare or parse summary text (section 6).

    If you extend coola¶

    • [ ] Equality: rewrite testers and handlers as testers that return a verdict or child pairs (section 4).
    • [ ] Hashing: port hashers to encode, replace SupportsHash.hash by __coola_hash__, move the secret policy to the registry (section 5).
    • [ ] Summary: port summarizers to summarize(data, config, *, compact) (section 6).
    • [ ] Recursive: port transformers to expand (section 7).
    • [ ] Iterator: port iterators and child finders to find_children (section 8).
    • [ ] Registry: replace DataclassMarker, find, resolve_or and BaseTypeDispatchRegistry (section 3).
    • [ ] Reducer: subclass BaseReducer instead of BaseBasicReducer (section 11).
    • [ ] I/O: rename load to _load in custom loaders and drop their equal (section 16).

    If you use a specific package¶

    • [ ] Factory: replace _init_: __new__ and the _init_ names that start with _, and resolve nested configurations before passing them under an allow-list (section 9).
    • [ ] Random: replace the removed names and give set_rng_state a state with the registered keys (section 10).
    • [ ] Reducer: pass descending by keyword and create TorchReducer() explicitly for tensors (section 11).
    • [ ] Nested: pass the options by keyword, import get_first_value from coola.utils.mapping, and read the stricter conversions (section 12).
    • [ ] Utils: update the import paths, replace the import decorators and the raise_<pkg>_missing_error functions, and read the smaller behaviour changes (section 13).
    • [ ] Display: pass force of configure_colorlog_logging by keyword and read the new pydantic output (section 14).
    • [ ] Testing: import the marks from coola.testing.marks and load the fixture with pytest_plugins (section 15); install the testing extra (section 1).
    • [ ] SciPy sparse matrices: install the scipy extra to compare them (section 1).

    Detailed changes¶

    Sections 1 to 3 apply to the whole library. Sections 4 to 11 follow the packages in order of use, section 12 covers coola.nested, sections 13 to 15 the helpers, and sections 16 to 19 the new packages.

    Part 1: Whole library (sections 1 to 3)¶

    1. Packaging: Python 3.11, New Extras¶

    Affects: Everyone who installs coola.

    Before After
    requires-python = ">=3.10" >=3.11 (Python 3.15 is supported)
    No extra for SciPy pip install coola[scipy] (scipy>=1.13): the equality tester of the sparse matrices
    coola.testing imports pytest with no declared dependency pip install coola[testing] (pytest>=8.0)
    polars>=1.0,<2.0 polars>=1.0,<3.0
    torch extra on every Python version Not installed on Python 3.15 (python_full_version < '3.15' marker)
    dependencies = [] Unchanged: coola still has no required dependency

    The jax, numpy, packaging, pandas, pyarrow, pydantic, xarray, colorlog and rich extras are unchanged. The development tools changed (ty replaces pyright; black and mutmut are removed), which matters to contributors only.

    2. Exceptions That Changed Type¶

    Affects: Code that catches RuntimeError, KeyError or RecursionError raised by coola.

    Before After
    registry.register(...), register_many(...) and the register_* functions raise RuntimeError for a duplicate AlreadyRegisteredError, a ValueError: except RuntimeError no longer catches it (exist_ok=True is unchanged)
    registry[key], unregister(key) raise a KeyError KeyNotRegisteredError, or TypeNotRegisteredError for a type: both are KeyError (the message is no longer escaped by repr)
    raise_package_missing_error, check_package and raise_<pkg>_missing_error raise RuntimeError MissingPackageError, a subclass of ModuleNotFoundError and RuntimeError: both except clauses still work
    objects_are_equal and objects_are_allclose raise RecursionError beyond max_depth=1000 MaxDepthExceededError, an Exception, beyond max_depth=100: raise max_depth for a deeper structure
    EmptySequenceError is an Exception A ValueError
    timeblock("no placeholder") raises RuntimeError ValueError (the message must contain {time})
    A rename that gives two equal keys keeps one of them DuplicateKeyError, a KeyError and a ValueError (section 12.3)
    RecursionError for a deep structure in recursive_apply, dfs_iterate, summarize and the coola.nested functions No limit: the engines use an explicit stack (a cycle raises ValueError)

    The messages of the validations changed too (section 19): a test that matches a message must be updated.

    3. coola.registry: Two Classes, Fallbacks, Pickling¶

    Affects: Code that builds, subclasses or registers into a registry, or catches its errors.

    Before After
    registry.register(DataclassMarker, handler) registry.register_fallback(dataclasses.is_dataclass, handler)
    from coola.registry import DataclassMarker Removed; the dataclass handler is in registry.fallbacks(), not in items() / len()
    BaseTypeDispatchRegistry, registry.find(t), registry.resolve_or(t) Removed; the registries of the packages are TypeRegistry subclasses: use registry.resolve(t)
    registry.register(key, value, True), register_many(mapping, True) exist_ok is keyword-only: register(key, value, exist_ok=True)
    registry.equal(other, equal_nan=True) registry.equal(other): the entries are compared with ==, and a registry equals its copy
    A duplicate registration raises RuntimeError; a missing key raises KeyError AlreadyRegisteredError (a ValueError, not a RuntimeError); KeyNotRegisteredError (a KeyError)
    A hasher for object makes the hashing fallbacks unreachable object is the last resort everywhere: type > fallback > object
    HasherRegistry.register_fallback(predicate, hasher) accepts a duplicate predicate A duplicate predicate raises AlreadyRegisteredError (exist_ok=True replaces it, keeping its place)
    HasherRegistry.unregister_fallback(predicate) returns None It returns the hasher and raises KeyNotRegisteredError for an unknown predicate
    repr(registry) printed (state): TypeRegistry(...); a hashing fallbacks list One display: one (key): value line per entry, then (fallback) lines and the pending lazy groups
    register_lazy(["builtins", "decimal"], f) then register_lazy("builtins", g) failed Both groups stay and load; register_lazy is a method of TypeRegistry only
    pickle.dumps(registry) and copy.deepcopy(registry) raised TypeError They work; a spawn worker can receive a registry

    Before:

    from coola.registry import DataclassMarker

registry.register(DataclassMarker, MyDataclassHandler())

    After:

    from dataclasses import is_dataclass

registry.register_fallback(is_dataclass, MyDataclassHandler())

    A handler registered for the type of a dataclass still has priority over the fallback. A fallback also supports the virtual subclasses of an abstract base class (the MRO lookup does not call issubclass): registry.register_fallback(lambda t: issubclass(t, Sequence), handler).

    Part 2: Core packages (sections 4 to 11)¶

    4. coola.equality: One Engine, Testers That Return a Verdict or Child Pairs¶

    Affects: Custom equality testers and handlers, code that uses show_difference=True, and tests that depend on comparison edge cases.

    The handler chain is replaced by testers that use an engine. A tester never recurses and never checks the identity, the type, the depth or the cycles: the engine does. The tester receives two objects of the same type and the engine (ctx), and returns either a verdict or the child pairs (actual, expected, path part) that must all be equal.

    Example (v2.0):

    >>> from coola.equality import AttributeName, BaseEqualityTester, compare, objects_are_equal
>>> class Point:
...     def __init__(self, x, y):
...         self.x = x
...         self.y = y
>>> class PointEqualityTester(BaseEqualityTester[Point]):
...     def objects_are_equal(self, actual, expected, ctx):
...         return (
...             (actual.x, expected.x, AttributeName("x")),
...             (actual.y, expected.y, AttributeName("y")),
...         )
>>> from coola.equality import get_default_registry
>>> registry = get_default_registry().copy()
>>> registry.register(Point, PointEqualityTester())  # or register_equality_testers({...})
>>> objects_are_equal(Point(1, 2.0), Point(1, 2.0), registry=registry)
True
>>> result = compare(Point(1, 2.0), Point(1, 3.0), registry=registry)
>>> result.path
('y',)

    A leaf tester returns a verdict and gives the reason with ctx.fail, which returns False. The reason can be a function: it is called only when the difference is explained.

    class VersionEqualityTester(BaseEqualityTester[Version]):
    def objects_are_equal(self, actual, expected, ctx):
        return actual.number == expected.number or ctx.fail(
            lambda: f"versions differ: {actual.number} vs {expected.number}"
        )

    Migration of the v1.1 API (handlers and chain testers):

    Before After
    BaseChainEqualityTester, HandlerEqualityTester, create_chain A BaseEqualityTester with one method objects_are_equal(a, e, ctx)
    BaseEqualityHandler, SameObjectHandler, SameTypeHandler, ... Removed: the engine checks the identity and the type
    config.registry.objects_are_equal(a, b, config) (recursion) Return the child pair (a, b, path part)
    report_difference(config, message, path=...) return ctx.fail(reason, *path)
    check_recursion_depth, track_comparison, HandlerCycleError Removed: the engine owns the depth and the cycles
    tester.equal(other) tester == other (same type and same attributes)
    EqualityConfig(atol=..., rtol=...), config.reports EqualityConfig(tolerance=Tolerance(...)); the config is frozen
    Engine(registry, config) Engine(config, explaining=False)
    PandasDataFrameEqualityTester, PolarsSeriesEqualityTester, ... TableEqualityTester(adapter), registered by the default registry
    from coola.equality.handler import ... Private (coola.equality._helpers); use coola.equality
    RecursionError when max_depth is exceeded (default 1000) MaxDepthExceededError, a plain Exception (default max_depth=100)
    objects_are_equal(..., show_difference=True) Removed (TypeError): see "Explaining a difference" below
    BaseEqualityHandler and the handlers: SameObjectHandler, SameTypeHandler, SameLengthHandler, SameAttributeHandler, SameShapeHandler, SameDTypeHandler, SameDataHandler, TrueHandler, FalseHandler, EqualHandler, EqualNanHandler, ScalarEqualHandler, NanEqualHandler, ObjectEqualHandler, TolerantEqualHandler, AllCloseNanHandler, MappingSameKeysHandler, MappingSameValuesHandler, SequenceSameValuesHandler and the handlers of NumPy, JAX, torch, pandas, polars and PyArrow Removed: a tester returns a verdict or child pairs
    The protocols SupportsEqual, SupportsEqualNan, SupportsAllCloseNan, SupportsTolerantEqual, SupportsShape, SupportsDType, SupportsData Removed: the objects keep the methods (equal(other), equal(other, equal_nan), allclose(other, rtol, atol, equal_nan)) and EqualEqualityTester, EqualNanEqualityTester and TolerantEqualEqualityTester call them (a protocol is not needed to register a type)
    PandasDataFrameEqualityTester, PandasSeriesEqualityTester, PolarsDataFrameEqualityTester, PolarsSeriesEqualityTester, PolarsLazyFrameEqualityTester, PyarrowEqualityTester TableEqualityTester(adapter) (a polars LazyFrame is compared like any other table)
    frame_equal, series_equal, handlers_are_equal, get_array_impl_class Removed

    Changes of the results:

    The rules are the same for every container and every library. A comparison can change in these cases:

    • bool and the members of an enum.Enum are labels: the tolerance never applies to them (also IntEnum, numpy.bool_ and pandas booleans).
    • An integer difference is computed in integers: 2**62 and 2**62 + 1 are different with atol=0.5 in an array, as they are in a list.
    • float16, bfloat16 and float32 are compared in double precision (no wrong True at the edge of the range).
    • MappingProxyType and array.array are compared like a mapping and a sequence.
    • pandas, polars and PyArrow numbers follow the tolerance; the nested and object cells are compared by the library (equals), without tolerance. The tolerance does not apply to an index.
    • A table (data frame, series, index, Arrow table) is one leaf of the explanation: the path stops at the table and the reason names the first column that differs.
    • OrderedDict keeps its order, a dict does not. A cycle is equal. A nesting deeper than max_depth raises MaxDepthExceededError.

    Explaining a difference: show_difference removed.

    show_difference=True (a log message) is replaced by two functions that explain the first difference only, on demand: compare returns a ComparisonResult and assert_objects_equal / assert_objects_allclose raise an AssertionError. objects_are_equal and objects_are_allclose format nothing.

    Before:

    import logging

logging.basicConfig(level=logging.INFO)
objects_are_equal(actual, expected, show_difference=True)

    After:

    >>> from coola.equality import compare, assert_objects_equal
>>> result = compare({"a": [1, 2, 3]}, {"a": [1, 2, 4]})
>>> result.equal
False
>>> result.path
('a', 2)
>>> print(result.format_message())
objects are not equal at actual['a'][2]
numbers are different:
  actual   : 3
  expected : 4
>>> assert_objects_equal({"a": 1}, {"a": 2})
Traceback (most recent call last):
    ...
AssertionError: objects are not equal at actual['a']
numbers are different:
  actual   : 1
  expected : 2

    compare(actual, expected, rtol=0.0, atol=0.0, ...) takes the same keywords as objects_are_allclose (exact by default). ComparisonResult has equal, path (keys, positions, AttributeName, Element) and reason, and no actual / expected fields.

    5. coola.hashing: One Engine, encode, a New Format¶

    Affects: Everyone who stores a hash or a stable identifier, custom hashers, and code that handles secrets.

    Every hash value changes (new encoding, format version coola-hash-2, short leaves inlined in the preimage of their parent), so every stable identifier changes too: generate_stable_content_id and generate_stable_uuid5 return other values. Regenerate any stored hash or identifier.

    Before After
    Hasher.hash(data, registry, *, length, ignore_unhashable) Hasher.encode(data): returns tagged(tag, payload) (a leaf) or Node(tag, children)
    A hasher calls registry.hash(child, length=..., ignore_unhashable=...) The children are in the Node; the engine hashes them
    hash_string, hash_bytes, hash_tagged, hash_enum, hash_path Removed: use hash_object; tagged and digest are the building blocks of a hasher
    SupportsHash.hash(registry, length, ignore_unhashable), HashableHasher __coola_hash__(self) -> object (the content, not a hash), SupportsCoolaHash, ContentHasher
    PydanticModelHasher(on_secret=...), hash_pydantic_model, unwrap_secrets SecretHasher(on_secret) and get_secret_hashers(on_secret), registered in a registry
    "exclude" removed the key or the item of a secret "exclude" hashes a constant: the position of a secret is kept
    A secret in a dict or a dataclass raised, or was TypeNotRegisteredError The policy of the registry applies wherever the secret is
    hash_object(data, registry, 32), register_hashers(mapping, True) Keyword-only: hash_object(data, registry=registry, length=32), register_hashers(mapping, exist_ok=True)
    HasherRegistry.hash(data, 16) HasherRegistry.hash(data, length=16)
    ValueError("... nested too deeply") at about 500 levels No limit: the traversal uses an explicit stack
    A DAG costs one visit per path A shared container is hashed once
    length applied to every node: hash(x, length=16) was not a prefix of length=128 One digest cut at the end: a hash is the start of the longer ones
    A dataclass field with compare=False was hashed Only the compare=True fields are hashed
    memoryview hashed like bytes; UserString and MappingProxyType failed Own tag (memoryview), UserString and MappingProxyType are hashed
    A pandas object named NaN and one named None had different hashes Same hash

    Before:

    class PointHasher(BaseHasher[Point]):
    def hash(self, data, registry, *, length=64, ignore_unhashable=False):
        return registry.hash((data.x, data.y), length=length, ignore_unhashable=ignore_unhashable)

    After:

    class PointHasher(BaseHasher[Point]):
    def encode(self, data):
        return Node("Point", [data.x, data.y])

    To reveal or exclude secrets, build a registry:

    registry = get_default_registry().copy()
registry.register_many(get_secret_hashers("reveal"), exist_ok=True)
hash_object(model, registry=registry)

    6. coola.summary: One Engine, One Option Object¶

    Affects: Custom summarizers, code that passes options to a summarizer, and code that parses summary text.

    Before After
    Summarizer.summarize(data, registry, depth, max_depth) returns a str and recurses Summarizer.summarize(data, config, *, compact) returns a str (a leaf) or a Node (a container)
    registry.summarize(data, depth, max_depth) registry.summarize(data, config=None) with a SummaryConfig
    SequenceSummarizer(max_items=3), DefaultSummarizer(max_characters=50), num_spaces=4 summarize(data, max_items=3, max_characters=50); the indentation is 2 spaces and is not an option
    NDArraySummarizer(show_data=True), PandasDataFrameSummarizer(max_fields=2) summarize(data, show_data=True), summarize(data, max_items=2)
    max_items=-1 and max_characters=-1 for "no limit" max_items=None and max_characters=None
    summarize(data, 2) and register_summarizers(mapping, True) TypeError: summarize(data, max_depth=2) and register_summarizers(mapping, exist_ok=True)
    max_depth=True and max_depth=1.5 accepted TypeError
    BaseCollectionSummarizer, BaseFieldsSummarizer, MAX_FIELDS Removed. format_fields(fields, max_fields) has no default for max_fields
    BaseMetadataSummarizer(show_data) with _describe(data) BaseMetadataSummarizer() with _describe(data) returning fields; a table returns ("columns", pairs)
    repr and equal to write in every summarizer BaseSummarizer gives Name() and "same type"
    RecursionError for a nesting of a few hundred levels No RecursionError: the engine uses an explicit stack
    A self-referencing container is repeated up to max_depth <cycle> where it comes back
    A __len__, a property or a __iter__ that raises makes summarize raise <class ...> <summary failed: ExcType> and the rest of the summary is intact
    field(repr=False) fields of a dataclass are printed They are not shown
    UserString is a list of characters, MappingProxyType is printed whole A leaf, and a mapping
    A named tuple has the labels (0), (1) The field names

        return f"Point(x={data.x}, y={data.y})"  # a leaf


class TreeSummarizer(BaseSummarizer[Tree]):
    def summarize(self, data: Tree, config: SummaryConfig, *, compact: bool) -> Node:
        # a container: the engine recurses, summarizes the children with the summarizer of their
        # type and applies max_items, max_depth and the cycle check
        return Node(
            f"Tree (children={len(data.children)})", enumerate(data.children), len(data.children)

    11. coola.reducer: One Base Class That Owns the Checks¶

    Affects: Custom reducers, and code that calls auto_reducer() for tensors.

    The changes of coola.reducer:

    • auto_reducer() returns NumpyReducer if NumPy is installed, else NativeReducer. It no longer returns TorchReducer when PyTorch is installed (it is slower on a list and slow to import): create TorchReducer() explicitly for tensors that live on a device.
    • BaseBasicReducer is removed. Subclass BaseReducer, which now owns the checks (empty input, iterator, options, shape) and calls the private computations _max, _mean, _median, _min, _quantile, _std and _sort. _is_empty and _check_values are removed; implement _prepare to convert or validate the input if needed.
    • sort(values, *, descending=False): descending is keyword-only.
    • EmptySequenceError is a ValueError.
    • The input is a sequence of real numbers (list, tuple, range) or a one-dimensional array / tensor for the backend. An iterator, a set, a str, an n-d or 0-d array, a complex number, an integer beyond 64 bits (NumPy and PyTorch) or a Decimal raise TypeError or ValueError with the same text in every backend (they used to return a value or raise AttributeError, RuntimeError, ...). NativeReducer rejects arrays and tensors: use NumpyReducer or TorchReducer.
    • quantile raises ValueError for a quantile outside [0, 1] (or NaN) in the three backends, before the values are read.
    • NativeReducer.mean uses statistics.fmean: it is much faster and the last bit of a float mean can differ.

    A caller that needs mutual exclusion around a read-modify-write of one file takes a lock of its own around the read and the write: save never provided it. A temporary file .<name>-<uuid><ext> left by a process killed during a save is hidden and safe to delete.

    18. coola.rounding: One Rule, One Registry¶

    Affects: Only code written against the development branch: the package is new since 1.1.10.

    round_values follows one rule: a float is read as the decimal that repr shows, and the three modes act on that decimal (see the user guide).

    Before After

    ceil(5.5200000000000005, 2) is 5.52 (below the input) 5.53: floor(x) <= x <= ceil(x) always
