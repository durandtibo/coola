    Architecture of coola.hashing¶

    This page describes the design of the coola.hashing package for contributors: the invariants, the contracts between the parts, and the decisions behind them. The rules that users rely on are in the user guide; the API is in the reference.

    Overview¶

    The package has one engine, one extension point and one encoding rule. A hasher only describes the content of a type: encode(data) returns the bytes of a leaf (tagged(tag, payload)) or a Node(tag, children, ordered, group). The engine (coola.hashing.engine) owns everything else: the dispatch by type (once per type and per call), the digests, the order rule, the cycles, the shared containers, the depth and the placeholder of ignore_unhashable. This is the same split as equality (the engine owns identity, type, depth and cycles; a tester returns the child pairs) and recursive (a transformer returns the children).

    hash_object(data, *, registry=None, length=64, ignore_unhashable=False)
        |   validates length; one registry; one call = one engine run
        v
digest_of(data, registry, ...)       explicit stack of frames; per-call type -> hasher cache and memo
        |-- hasher   = registry.find_hasher(type(data))     MRO, fallbacks, Enum rule
        |-- encoding = hasher.encode(data)                  pure: no registry, no recursion
        |        bytes -> leaf:  digest = BLAKE2b(0x00 + encoding)
        |        Node  -> push the children; when done:
        |                 digest = BLAKE2b(0x01 + tag + 0x00 + entries of the children)
        |                 (an entry is 0xFF + digest, or size + leaf for a leaf of at most 64 bytes)
        v
the 64-byte digest of the root  ->  hex()[:length]
    Decision Why
    encode returns a description, the engine hashes cycles, depth, sharing, length and the placeholder cannot be forgotten
    A leaf of at most 64 bytes is inlined in the preimage of its parent a flat container makes one BLAKE2b call instead of one per item
    One 64-byte digest, cut at the end by length a hasher never sees length; a short hash is the start of a longer one
    The format version is the BLAKE2b person parameter two formats can never be confused; a change is one constant
    A shared container is hashed once per call (a memo by id) a hash is pure, so the memo is invisible; a DAG is linear
    A cycle raises ValueError the digest of a container in a cycle would depend on where it is reached
    Secrets are types with a hasher (SecretHasher) the policy is the one of the registry, wherever the secret is
    __coola_hash__ returns the content of a custom object, not a hash the object cannot bypass the engine and does not forward any option
    Only the compare=True fields of a dataclass equal dataclasses have the same hash

    See the user guide for the properties of the package.

    Design constraints¶

    1. Simple and easy to maintain. The package is 3,686 lines, 25 modules and 31 hash methods that all repeat the same four parameters (and 30 # noqa: ARG002 to silence the ones they do not use). The target removes the code that exists only to work around the design (the thread-local cycle state, two copies of it, the RecursionError translation, the signature inspection of _has_hash_method, the secret traversal of unwrap_secrets, the positional-argument shim) instead of adding code next to it.
    2. Major release. Breaking changes are fine and compatibility is not a design input: no adapter, no alias, no deprecation period. Every hash value changes (the encoding changes, section 3.4), so every stable identifier changes too. The release notes say so; the golden vectors are regenerated once, deliberately.
    3. Consistent with equality. "Equality drives hashing, not the reverse": equal objects must have the same hash, and where a hasher disagrees with objects_are_equal the hasher is changed .
    4. No slower than before, and the gate exists. tests/benchmarks/test_hashing_benchmark.py was added with this document, and the baseline of the previous version is saved (appendix). A design that is simpler but slower is rejected.
    5. Consistent with the siblings. The same input is handled the same way by equality, summary, recursive, iterator and hashing: dataclasses are entered, cycles are detected, there is no RecursionError, options are keyword-only, the engine owns the invariants and the type-specific class only describes its type.
    6. Optional libraries stay lazy. The package imports no optional library; the hashers of NumPy, torch, JAX, pandas, polars, pyarrow, xarray and pydantic are loaded the first time the registry looks for one of their types (register_lazy, unchanged).

    Architecture in detail¶

    hash_object(data, *, registry=None, length=64, ignore_unhashable=False)
        |   validates length; one registry (default: the singleton); one call = one engine run
        v
digest_of(data, registry, ignore_unhashable)           coola/hashing/engine.py   (about 60 lines)
        |   explicit stack of frames; per-call type -> hasher cache; per-call memo / ancestors
        |
        |-- hasher   = registry.find_hasher(type(data))        MRO, fallbacks, Enum rule
        |-- encoding = hasher.encode(data)                     pure: no registry, no recursion
        |        bytes  -> leaf: digest = BLAKE2b(0x00 + encoding)
        |        Node   -> push the children; when they are done:
        |                  digest = BLAKE2b(0x01 + tag + 0x00 + digests of the children)
        v
the 64-byte digest of the root  ->  hex()[:length]

    The engine owns the invariants (dispatch cache, composition, order rule, cycles, depth, sharing, placeholder). A hasher only describes the content of a type: a tagged byte string for a leaf, or a tag and the children for a container. That is the same split as equality (the engine owns identity, type, depth and cycles; a tester returns the child pairs) and recursive (a transformer returns the children and how to rebuild). registry, length and ignore_unhashable are no longer arguments of a hasher, so a hasher cannot forget a protection, cannot recurse and cannot leak a parameter.

    The hasher contract¶

    @dataclass(slots=True)
class Node:
    tag: str  # constant of the hasher
    children: Iterable[Any]  # the values to hash, consumed once, lazily
    ordered: bool = True  # False: the groups of children are sorted by digest
    group: int = 1  # number of consecutive children that form one unordered entry


Encoding = bytes | Node


class Hasher(Protocol[T_contra]):
    def encode(self, data: T_contra) -> Encoding:
        """A leaf (``tagged(tag, payload)``) or a ``Node`` that describes the content of ``data``."""


class BaseHasher(ABC, Generic[T]):  # convenience base class, as before
    @abstractmethod
    def encode(self, data: T) -> Encoding: ...

    Two helpers are public, so that a hasher never imports hashlib and the format stays in one place:

    • tagged(tag: str, payload: str | bytes = b"") -> bytes: tag, a NUL byte, payload (text is encoded in UTF-8 with surrogatepass: a lone surrogate never collides with a valid string).
    • digest(data: bytes) -> bytes: the 64-byte BLAKE2b of the package. A hasher uses it to reduce a big buffer (array values, the content of a bytes) to a fixed-width value before it enters the encoding, so the engine never copies a 50 MB preimage.

    Rules of the contract (documented in BaseHasher, checked by one parametrised unit test over the default registry, like NATIVE_SAMPLES in equality):

    1. encode is pure and cheap: it does not call the registry, does not recurse, does not modify data, and does not read the clock, the environment or the filesystem (ResolvedPathHasher is the documented exception). It does not depend on id(), on hash() or on the iteration order of a set or of a mapping (an unordered Node says so instead).
    2. It returns bytes (a leaf) or a Node. A leaf has no children: the engine digests it as is.
    3. Node.children may contain any value, including a value built on the spot (a list of field names, a NumPy array, a str dtype): each child is encoded by its own hasher, found by the registry, so a user who replaces the hasher of str or of ndarray changes every container that holds one.
    4. ordered=True: the position of a child matters. ordered=False: the children are cut into groups of group consecutive children (a mapping uses group=2: key, value), the digest of a group is the concatenation of the digests of its children, and the groups are sorted by digest. The result does not depend on the iteration order, and the keys need not be orderable.
    5. The tag is a constant of the hasher, never derived from type(data), except for the user-defined classes (dataclass, model, custom object, enum) whose qualified class name is the identity. A subclass therefore hashes like its base.
    6. An exception propagates unchanged.

    The extension example of the guide becomes the shortest possible one, with no registry and no length to remember:

    class PointHasher(BaseHasher[Point]):
    def encode(self, data):
        return Node("Point", [data.x, data.y])


register_hashers({Point: PointHasher()})

    The engine¶

    def digest_of(data, registry, ignore_unhashable):
    cache: dict[type, Hasher | None] = {}  # type -> hasher (None: placeholder), this call only
    memo: dict[int, tuple[object, bytes | None]] = {}  # id -> (object, digest); None = in progress

    def enter(obj):  # -> (frame, None) for a container, (None, digest) otherwise
        t = type(obj)
        if t not in cache:
            cache[t] = resolve(registry, t, ignore_unhashable)  # warns once per type
        hasher = cache[t]
        encoding = hasher.encode(obj) if hasher else tagged("unhashable", qualified_name(t))
        if type(encoding) is bytes:
            return None, blake2b(b"\x00" + encoding)
        seen = memo.get(id(obj))
        if seen is not None:
            if seen[1] is None:
                raise ValueError(f"Cannot hash a self-referencing {t!r}.")
            return None, seen[1]  # already hashed in this call (a shared container)
        memo[id(obj)] = (obj, None)  # keeps obj alive: its id cannot be reused in this call
        return Frame(obj, encoding, iter(encoding.children), []), None

    frame, result = enter(data)
    if frame is None:
        return result
    stack = [frame]
    while True:
        top = stack[-1]
        for child in top.children:  # resumes where it stopped
            child_frame, child_digest = enter(child)
            if child_frame is None:
                top.digests.append(child_digest)
            else:
                stack.append(child_frame)
                break
        else:  # children exhausted
            stack.pop()
            result = top.finish()  # groups, sort if unordered, BLAKE2b(0x01 + tag + 0 + digests)
            memo[id(top.obj)] = (top.obj, result)
            if not stack:
                return result
            stack[-1].digests.append(result)

    Design points:

    • No RecursionError, no thread-local, no lock. The state (stack, cache, memo) is local to the call, so threads and re-entrant calls (a hasher that calls hash_object) are independent. HasherRegistry.hash and hash_object delegate to this function; nothing else recurses.
    • Cycles and sharing in one dict. memo[id] = (obj, None) while a container is in progress, its digest afterwards. Meeting an object in progress is a cycle; meeting a finished one is a shared container and costs a dictionary lookup. The object is kept in the entry so that the id of a temporary child (a dict of fields built by a hasher) cannot be reused by another object in the same call. Only containers are memoized, never leaves.
    • The cycle check is after encode, so a leaf (a string, an array) never enters the memo, and a container is reported even if a custom hasher returns its own object as a child.
    • The per-call cache removes the registry lookup per node. A hasher registered during a call is not seen by this call (the next call sees it).
    • ignore_unhashable lives here only. The type is resolved once per call; a type with no hasher is replaced by tagged("unhashable", qualified_name) and a UserWarning is emitted once per type per call, with stacklevel pointing at the caller of hash_object. Without the option, the TypeNotRegisteredError carries the remedies (register a hasher, give the class a __coola_hash__, or pass the option).
    • Memory. Besides the input, the engine holds the digests of the children of the containers being built (about 100 bytes per child of a node in progress) and the memo. A flat list of one million items needs about 100 MB for the digests, like the previous hex strings. Streaming the digests of an ordered node into a running blake2b object would remove it; it is a three-line change if the benchmark shows a need.
    • func does not exist: a hasher's exception reaches the caller with its own traceback and no frame of the package between (the recursion of the previous version adds two per level).

    The encoding¶

    One rule for every hash, written once in engine.py and base.py:

    digest(x)  = BLAKE2b-512(preimage, person = b"coola-hash-1")           # 64 bytes, always
leaf       : preimage = 0x00 + tag + 0x00 + payload                     # what `encode` returned
node       : preimage = 0x01 + tag + 0x00 + d1 + d2 + ... + dn          # fixed-width children
unordered  : the groups of `group` children are concatenated, then sorted, then joined
hash_object(x, length=n) = digest(x).hex()[:n]                         # n characters
    • Fixed-width children make the concatenation unambiguous without delimiters. The leading 0x00/0x01 byte makes a leaf and a node with the same tag different by construction.
    • length is chosen by the caller and cuts the end. The caller asks for 2 to 128 characters . Every digest is a full 64-byte BLAKE2b, so the hash of any length is the start of the longest one, a hasher never sees length, and length is validated once, before the traversal. The default length=64 is the first half of the digest.
    • The format version is the person parameter of BLAKE2b (at most 16 bytes, free): the digests of two formats can never be mistaken for one another, and a change of the encoding is one constant, coola-hash-2, plus the regenerated golden vectors.
    • Tag rule. A scalar and a stdlib container have a constant tag (int, str, list, OrderedDict, date, UUID, Decimal, Path, numpy.ndarray, ...), so a subclass hashes like its base and a library moving a class to another module does not change a hash. A user-defined type (dataclass, model, enum, custom object) uses module.qualname, because the class is its identity. A tag is never derived from type(data) anywhere else. A named tuple adds its class name and field names to the tag of tuple (so it differs from a plain tuple and from another named tuple).
    • Big payloads are reduced with digest() by the hasher (arrays, bytes), so the preimage of a leaf is a few hundred bytes at most.

    Registry and dispatch¶

    HasherRegistry(TypeRegistry[Hasher]) keeps its role: map types to hashers and find the most specific one along the MRO, then the fallbacks (registration order), then object if one is registered (the default registry has none: an unsupported type fails loudly). It keeps find_hasher and has_hasher and gets one more rule, in find_hasher:

    A subclass of Enum resolves to the hasher of Enum unless a hasher is registered for the enum class itself (or for a parent that is not a builtin base of the mixin).

    StringHasher and ReprHasher lose their isinstance(data, Enum) branches, and HasherRegistry.hash is digest_of(...).hex()[:length] with the validation of length. The class is then about 120 lines instead of 239. The registry has no knowledge of cycles, placeholders or the recursion limit.

    get_default_registry() is the singleton with the built-in hashers, the entries of the plugin group coola.hashing.hashers and the lazy groups; get_stable_registry() is the same without the plugins and is the registry of generate_stable_content_id and generate_stable_uuid5 (unchanged, 22.4). register_hashers(mapping, *, exist_ok=False) is keyword-only for exist_ok.

    Library hashers¶

    The hashers of the optional libraries lose their registry plumbing (_hash_values(values, registry, length, ignore_unhashable) is called twenty times in pandas.py). They return a Node whose children are plain values; the engine hashes each one with the hasher of its type:

    Library encode(data)
    NumPy numeric dtype: leaf tagged("numpy.ndarray", f"{dtype}\0{shape}\0" + digest(canonical bytes)) (masked arrays add the digest of the mask); object dtype: Node("numpy.ndarray", [dtype, shape, items])
    torch leaf as NumPy with the tag torch.Tensor, the dense CPU values, no device and no requires_grad
    JAX leaf as NumPy with the tag jax.Array
    pandas Node("pandas.DataFrame", [columns key, index key, dtype and values of each column]); a key is (names, dtype, values); a categorical dtype adds its categories and ordered; a missing value is None (22.1); a NaN name is None
    polars Node("polars.DataFrame", [name, str(dtype), values, ...]) per column; numeric columns without nulls pass the NumPy array
    pyarrow the fixed-width types as NumPy leaves with the digest of the validity bitmap; the other types as a Node over to_pylist()
    xarray Node("xarray.DataArray", [name, dims, values, coords, attrs]) (the same three shapes as before)

    The semantics of every library hasher are unchanged (the rules of the guide: dtype, shape, values, no layout, -0.0 and NaN canonical). Only the way the parts are combined changes. The helpers that three modules share (canonicalize_floats, hash_array_content) keep their place in coola.hashing.numpy.

    Custom objects: __coola_hash__¶

    class SupportsCoolaHash(Protocol):
    def __coola_hash__(self) -> object: ...

    A class that cannot be a dataclass says what its content is and the engine hashes it (with the tag custom:module.Class, so two classes with the same content differ):

    class Point:
    def __coola_hash__(self):
        return (self.x, self.y)

    This replaces SupportsHash.hash(registry, length, ignore_unhashable): the object no longer recurses, so it cannot bypass the cycle check, nobody forwards length, and the fallback predicate is callable(getattr(t, "__coola_hash__", None)) with no signature inspection. The dunder name cannot collide with a method of a library (polars.Series.hash). A dataclass keeps the dataclass hasher even if it defines __coola_hash__ (type > fallback order, then registration order of the fallbacks), as it did for hash().

    Secrets and pydantic¶

    Secrets become types with a hasher, so the policy is the one of the registry and applies wherever a secret is, not only in the fields of the model:

    class SecretHasher(BaseHasher[SecretStr | SecretBytes]):
    def __init__(self, on_secret: Literal["error", "reveal", "exclude"] = "error"): ...

    # "error":   ValueError, the message never contains the secret
    # "reveal":  leaf tagged("pydantic.SecretStr", value)
    # "exclude": leaf tagged("pydantic.SecretStr")   (the value is not part of the hash)

    PydanticModelHasher.encode is Node("pydantic:module.Class", fields and extras), nothing else: unwrap_secrets, hash_pydantic_model, the on_model callback, the second thread-local and the PLC0415 import of interface disappear. The default registry registers SecretHasher("error") for SecretStr and SecretBytes in the pydantic lazy group. To reveal or exclude, a caller builds a registry:

    registry = get_default_registry().copy()
registry.register_many(get_secret_hashers("reveal"), exist_ok=True)  # SecretStr and SecretBytes
hash_object(model, registry=registry)

    Behaviour changes, documented: a secret in a dict or in a dataclass is now governed by the same policy as in a model (before: an error or a TypeNotRegisteredError); "exclude" no longer removes the key or the item, it replaces the value by a constant (the position of a secret is part of the schema of the class, so it is not information; the value still is never hashed).

    Errors and options¶

    Situation Behavior
    length is not an even int from 2 to 128 ValueError before any traversal; a bool or a float is rejected with the same message
    No hasher for a type TypeNotRegisteredError (a KeyError) with the remedies, or a lossy placeholder and one UserWarning per type
    A container that contains itself ValueError("Cannot hash a self-referencing <type>.")
    Nesting of any depth works; the only limit is memory (no RecursionError, no ValueError)
    A secret with on_secret="error" ValueError, without leaking the value
    An exception raised by a hasher propagates unchanged

    Package Change

    Decision record¶

    D1. One contract: encode returns a description, the engine hashes. Recommended: yes. It is the only way to make cycles, depth, sharing, length and the placeholder properties of the engine instead of the discipline of 31 methods, and it is what equality, summary and recursive already do. Alternative: keep hash(data, registry, *, length, ignore_unhashable) -> str and move the parameters into a context object (hash(data, ctx)). It removes the noqa but a hasher still recurses, so to stay and the engine cannot be an explicit loop.

    Decision: yes

    D2. Who chooses the length of the hash. Decision: the caller controls the hash length: hash_object(x, length=16) returns 16 characters (an even int from 2 to 128). Internally one 64-byte digest is computed and the first length characters are kept, which is the simplest way to meet the requirement (no size argument in the engine, no special case for the root). A side effect is that the hash of a shorter length is the start of the longer one, so a short id can be matched against a stored full hash with startswith. The alternative (the root alone computed with digest_size = length // 2) gives the same API and independent values at each length, at the cost of one more argument in the engine; it was not chosen.

    Decision: I want to be able to control the hash length.

    Applied: the Fixed width, user-chosen property, the encoding rule of, the registry and the length tests of.

    D3. Memoize the shared containers. Recommended: yes. Unlike recursive_apply, a hash is pure, so the memo is unobservable, and it turns a DAG from exponential to linear. The cost is one dictionary entry per container and the objects kept alive until the call ends, which also makes the id reuse of temporary children impossible. Alternative: no memo and a plain set of ancestors for the cycles; simpler by three lines, 2^20 paths stay 4 s.

    Decision: yes

    D4. Cycles. Recommended: keep ValueError. objects_are_equal accepts a cyclic structure and says "equal", so strictly "equal implies the same hash" is violated by a cycle. A deterministic back-reference (the distance to the ancestor) would make a cycle hashable, but the digest of a container in a cycle then depends on where it is reached from, which breaks the memo of D3 and the "hash of a child is reusable" property. A cycle in a hashed configuration is a bug nine times out of ten; the loud error is the better default. Revisit if a user needs it.

    Decision: keep ValueError

    D5. The protocol of a custom object. Recommended: a method that returns the content (__hash_content__); decided: __coola_hash__(self) -> object. The object says what its content is and does not recurse; no signature inspection, no collision with a library hash method. Alternative: keep hash(registry, length, ignore_unhashable), which forces the engine to support a re-entrant, parameterised call and keeps . Naming alternatives: __hash_content__, hash_content.

    Decision: __coola_hash__(self) -> object

    Applied:, 4, 5 and 7 and the tests use __coola_hash__, the protocol is SupportsCoolaHash, and ContentHasher keeps its name (it hashes the content the method returns).

    D6. Secrets are types with a hasher, and exclude replaces instead of removing. Recommended: yes. It deletes a second traversal (unwrap_secrets), a second thread-local and the asymmetry between a model and a dataclass. The policy is the one of the registry, so a caller that wants reveal builds a registry once. Alternative: keep the on_secret argument of the model hasher and the unwrap_secrets traversal, and live with .

    Decision: yes

    D7. Inline the short leaves in the preimage of their parent. Recommended: not now. It is 4 times faster than the previous version on flat containers instead of 1.5 to 2 times, but it needs two forms of child entry and a length prefix, and the plain composition already meets the gate. Do it only when a benchmark or a user shows that hashing a million-element list is on a hot path. Streaming the digests of an ordered node into a running blake2b object (memory) is the other optimisation held back for the same reason.

    Decision: not now

    D8. Remove the public leaf functions (hash_string, hash_bytes, hash_tagged, hash_enum, hash_path, hash_pydantic_model). Recommended: remove. They hash one value under a tag with a length, which is hash_object for a scalar, and they keep length in the leaf code. A caller that wants a plain BLAKE2b of a string uses hashlib. tagged and digest stay because a custom hasher needs them.

    Decision: remove

    D9. A format version in the digest. Recommended: yes, person=b"coola-hash-1". It costs nothing, it makes two formats impossible to confuse (a stored hash of an older format never equals a new one by accident) and it turns a deliberate format change into a one-line constant plus the golden vectors. Alternative: no version and rely on the golden vectors alone.

    Decision: yes

    D10. Keep the stable registry and the plugin group. Recommended: keep. The plugin group is how a library adds its types, and get_stable_registry() is what keeps the identifiers independent of the plugins (22.4). Nothing in this design changes them except the encode contract of the entries.

    Decision: keep

    D11. Only compare=True fields of a dataclass. Recommended: yes. It is the rule of objects_are_equal, so equal dataclasses have the same hash. A cache or a lazily computed field should not make two equal objects different. A user who wants every field registers DataclassHasher(all_fields=True) for the type, or a hasher of their own (the option is the one extension of the class and is not needed otherwise: leave it out until someone asks).

    Decision: yes

    Not covered¶

    • Hashes of types that equality supports and hashing does not (14.4). After this design, the next candidates are Index, MultiIndex and Categorical as values, np.datetime64, np.timedelta64, array.array, dict_keys, dict_values, dict_items, slice, Ellipsis, re.Pattern, torch.dtype and torch.device. Each is one hasher and one registration now that the contract is encode; they are separate items.
    • Functions, classes and other callables are not hashed (a class in a configuration needs its own hasher). A type hasher by qualified name is a one-line registration if a user asks.
    • Hashing the content of a file (ResolvedPathHasher hashes the path, not the file).
    • A cyclic structure and a structure that changes during the call (no lock).
    • Streaming and parallel hashing: the engine is a single loop; a huge array is already one call of BLAKE2b on a buffer.
    • Meta and float8 tensors (14.5): unchanged by this design; a separate item.
    • The equality side of 22.4: unchanged.
