# Migration Guide: v1.1 to v2.0

This guide explains how to migrate your code from `coola` version `1.1.x` to version `2.0.x`.

## Overview of Changes

The main changes in version 2.0 are the `expand` protocol of `coola.recursive` (the engine now
recurses, and a transformer only describes the children of one object) and the single child finder
of `coola.iterator` (one registry and one `find_children` for `dfs_iterate` and `bfs_iterate`).
`coola.factory` has one way to import a target, one way to call it and one way to ask what it builds.

## Migration Checklist

- [ ] Port the custom `coola.recursive` transformers to `expand` (section 1)
- [ ] Port the custom `coola.iterator` iterators and child finders to `find_children` (section 2)
- [ ] Replace `_init_: __new__` and the `_init_` names that start with `_` by a public class method,
      and resolve the nested configurations before passing them under an allow-list (section 3)

## Detailed Changes

### 1. Recursive Transformers: the `expand` Protocol

| Before                                                                                  | After                                                                                       |
| --------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------- |
| `Transformer.transform(data, func, registry)`                                           | `Transformer.expand(data)`: returns `None` (a leaf) or `(children, rebuild)`                |
| A transformer recurses through `registry.transform`                                     | The engine recurses: a transformer cannot forget the cycle check or the depth limit         |
| A dataclass is a leaf; `enter_dataclasses()` enters it                                  | A dataclass is entered by default; `enter_dataclasses` is removed                           |
| `dfs_iterate` and `bfs_iterate`: a dataclass is a leaf; `enter_dataclasses()` enters it | A dataclass is entered by default; `enter_dataclasses` is removed from `coola.iterator`     |
| `dataclasses.replace` rebuilds a dataclass                                              | A shallow copy with the fields set: `init=False` fields are transformed, no `__post_init__` |
| `ConditionalTransformer`                                                                | Removed: guard `func`, or register `IdentityTransformer` for the type                       |
| `recursive_apply(data, func, registry)`                                                 | `recursive_apply(data, func, registry=registry)`                                            |
| `KeyFilterTransformer()` with `func` as the key predicate                               | `KeyFilterTransformer(key_predicate=...)`; `func` is the function of the values             |
| `register_transformers(mapping, True)`                                                  | `register_transformers(mapping, exist_ok=True)`                                             |
| `RecursionError` for a deep structure                                                   | No limit: the traversal uses an explicit stack                                              |

**Before:**

```python
class PointTransformer(BaseTransformer[Point]):
    def transform(self, data, func, registry):
        return Point(registry.transform(data.x, func), registry.transform(data.y, func))
```

**After:**

```python
class PointTransformer(BaseTransformer[Point]):
    def expand(self, data):
        return [data.x, data.y], lambda xs: Point(*xs)
```

A plugin of the group `coola.recursive.transformers` that implements `transform` must be ported to
`expand`. To keep a dataclass as a leaf, register `DefaultTransformer()` for its type (`DefaultChildFinder()` for
`dfs_iterate` and `bfs_iterate`).

### 2. Iterators: One Child Finder for Both Orders

| Before                                                                                 | After                                                                                         |
| -------------------------------------------------------------------------------------- | --------------------------------------------------------------------------------------------- |
| `coola.iterator.dfs` and `coola.iterator.bfs`                                          | Removed: import from `coola.iterator`                                                         |
| `BaseIterator.iterate(data, registry)` (DFS) and `BaseChildFinder.find_children` (BFS) | `BaseChildFinder.find_children(data)`: returns the children, or `None` for a leaf             |
| `IteratorRegistry`, `PathRegistry`                                                     | Removed: `ChildFinderRegistry` serves both orders                                             |
| `register_iterators` and `register_child_finders`                                      | `register_child_finders(mapping, *, exist_ok=False)`                                          |
| `get_default_iterator_registry()`                                                      | `get_default_registry()` (alias `get_default_child_finder_registry()`)                        |
| `DefaultIterator`, `IterableIterator`, `MappingIterator`, `DataclassIterator`          | `DefaultChildFinder`, `IterableChildFinder`, `MappingChildFinder`, `DataclassChildFinder`     |
| A leaf overrides `is_leaf` (BFS)                                                       | A leaf returns `None` from `find_children`; an empty container returns an empty iterable      |
| `registry.iterate(data)` and `registry.find_children(data)`                            | Removed: use `dfs_iterate(data, registry=registry)` or `bfs_iterate(data, registry=registry)` |
| `dfs_iterate(data, registry)` and `bfs_iterate(data, registry)` (deprecated)           | `registry` is keyword-only                                                                    |
| Plugin groups `coola.iterator.dfs` and `coola.iterator.bfs`                            | One group: `coola.iterator.child_finders`                                                     |
| `RecursionError` for a `dfs_iterate` structure nested about a thousand levels          | No limit: both orders use an explicit stack or queue                                          |
| `range`, a user `Collection` and a user `collections.abc.Set` are entered              | They are leaves, like in `recursive_apply` (register a child finder to enter them)            |
| `bfs_iterate` could raise a false `Cycle detected` for objects built by a child finder | Fixed: the ancestors are compared by identity                                                 |

**Before:**

```python
class ReversedListIterator(BaseIterator[list]):
    def iterate(self, data, registry):
        for item in reversed(data):
            yield from registry.iterate(item)
```

**After:**

```python
class ReversedListChildFinder(BaseChildFinder[list]):
    def find_children(self, data):
        return reversed(data)
```

A child finder returns the children in the order they are visited, and the same order is used by
`dfs_iterate` and `bfs_iterate`: a custom order for one traversal only is no longer possible. A
plugin of the group `coola.iterator.dfs` or `coola.iterator.bfs` must register a `ChildFinder` in
`coola.iterator.child_finders` instead.

### 3. Factory: Strict Contracts

| Before                                                                                        | After                                                           |
| --------------------------------------------------------------------------------------------- | --------------------------------------------------------------- |
| A target cannot receive an argument named `obj` or `cls`                                      | It receives every key that is not reserved, whatever its name   |
| `_init_="__new__"` or a name that starts with `_`                                             | `TypeError`: use a public class method or static method         |
| `_allowed_prefixes_` in the configuration of `resolve_object` (used when the caller has none) | Ignored: the allow-list always comes from the caller            |
| `factory(..., _allowed_prefixes_=[...])` with an argument that is `{"_target_": ...}`         | `ValueError`: resolve the nested configuration first            |
| `resolve_object` with a nested configuration and `allowed_prefixes`                           | `ValueError` (same reason)                                      |
| A `dict` with `_target_` and a `dict` subclass `cls`                                          | Built (the key `_target_` is reserved)                          |
| A `dict` without `_target_`                                                                   | Returned if it is an instance of `cls`, else `TypeError`        |
| `Counter({"_target_": 2})` passed to `resolve_object`                                         | Resolved as a configuration                                     |
| Missing module or attribute of a target                                                       | `ImportError: The target object does not exist: ...` everywhere |
| A target that returns `A \| B` with no subclass of `cls`                                      | Refused before the call                                         |
| `is_object_config({"_target_": 5}, int)`                                                      | `False` (was `TypeError`)                                       |
| Explicit `_init_="__init__"` with `resolve_object`                                            | The target is checked, like the default                         |

**Before:**

```python
resolve_object({"_target_": "mypkg.Model", "_init_": "__new__"})
```

**After:**

```python
resolve_object({"_target_": "mypkg.Model", "_init_": "from_config", "config": {...}})
```

An allow-list is a filter on a path, not a sandbox: never allow a prefix that contains a function
that resolves its arguments (`"coola"`, `"coola.factory"`, `pickle`, `eval`, ...).
