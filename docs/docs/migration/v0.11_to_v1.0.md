# Migration Guide: v0.11 to v1.0

This guide explains how to migrate your code from `coola` version `0.11.x` to version `1.0.x`.
Version 1.0 includes significant API reorganization to improve maintainability and extensibility.

## Overview of Changes

The main changes in version 1.0 are:

1. **Module reorganization**: Better structured package hierarchy
2. **Import path changes**: Top-level imports moved to subpackages
3. **Naming changes**: More consistent naming conventions (e.g., `comparators` → `tester`)
4. **Removed features**: Some modules were removed or merged (e.g., `formatters`)
5. **New equality engine**: One extension point (the tester), one iterative engine, no handler chain
6. **Explanations on demand**: `show_difference` is replaced by `compare` and `assert_objects_equal`

## Quick Migration Checklist

- [ ] Update imports for equality functions (`coola` → `coola.equality`)
- [ ] Update imports for summarization (`coola.summarizers` → `coola.summary`)
- [ ] Replace uses of formatters with summary functions
- [ ] Rewrite custom comparators, testers and handlers as testers that return a verdict or child pairs (section 3)
- [ ] Replace `show_difference=True` by `compare(...)` or `assert_objects_equal(...)` (section 4)
- [ ] Update module names (`reduction` → `reducer`)

## Detailed Changes

### 1. Top-Level Imports Removed

The main equality functions are no longer available at the top level.

**Before (v0.11):**

```python
from coola import objects_are_equal, objects_are_allclose
```

**After (v1.0):**

```python
from coola.equality import objects_are_equal, objects_are_allclose
```

**Migration:** Add `.equality` to your import statements.

### 2. Module Reorganization

Several modules have been renamed or reorganized:

| Feature                   | v0.11                         | v1.0                    | Status   |
| ------------------------- | ----------------------------- | ----------------------- | -------- |
| Equality functions module | `coola.comparison` (internal) | `coola.equality`        | Renamed  |
| Comparators               | `coola.equality.comparators`  | `coola.equality.tester` | Renamed  |
| Formatters                | `coola.formatters`            | N/A                     | Removed* |
| Summarizers               | `coola.summarizers`           | `coola.summary`         | Renamed  |
| Reduction                 | `coola.reduction`             | `coola.reducer`         | Renamed  |

*Use `coola.summary` instead of the removed `formatters` module.

**Note:** In v0.11, equality functions were available both at the top level (`from coola import`) and in `coola.comparison` module. In v1.0, they are only in `coola.equality`.

### 3. Equality Comparison System

The equality comparison system has been redesigned with a cleaner architecture.

#### Basic Usage (No Breaking Changes)

If you only use the basic equality functions, the migration is simple:

**Before (v0.11):**

```python
from coola import objects_are_equal, objects_are_allclose

objects_are_equal(actual, expected)
objects_are_allclose(actual, expected, rtol=1e-5, atol=1e-8)
```

**After (v1.0):**

```python
from coola.equality import objects_are_equal, objects_are_allclose

objects_are_equal(actual, expected)
objects_are_allclose(actual, expected, rtol=1e-5, atol=1e-8)
```

The function signatures and behavior remain the same.

#### Custom Equality Testers

The comparator system has been replaced by testers that use an engine. A tester never recurses and
never checks the identity, the type, the depth or the cycles: the engine does. The tester receives
two objects of the same type and the engine (`ctx`), and returns either a verdict or the child pairs
`(actual, expected, path part)` that must all be equal.

**Before (v0.11):**

```python
from coola.equality.comparators import BaseEqualityComparator


class PointComparator(BaseEqualityComparator):
    def clone(self):
        return PointComparator()

    def equal(self, other):
        return isinstance(other, PointComparator)

    def object_equal(self, tester, object1, object2, show_difference=False):
        if not isinstance(object2, Point):
            return False
        return tester.object_equal((object1.x, object1.y), (object2.x, object2.y))
```

**After (v1.0):**

```pycon
>>> from coola.equality import AttributeName, BaseEqualityTester, compare, objects_are_equal
>>> class Point:
...     def __init__(self, x, y):
...         self.x = x
...         self.y = y
>>> class PointEqualityTester(BaseEqualityTester[Point]):
...     def objects_are_equal(self, actual, expected, ctx):
...         return (
...             (actual.x, expected.x, AttributeName("x")),
...             (actual.y, expected.y, AttributeName("y")),
...         )
>>> from coola.equality import get_default_registry
>>> registry = get_default_registry().copy()
>>> registry.register(Point, PointEqualityTester())  # or register_equality_testers({...})
>>> objects_are_equal(Point(1, 2.0), Point(1, 2.0), registry=registry)
True
>>> result = compare(Point(1, 2.0), Point(1, 3.0), registry=registry)
>>> result.path
('y',)

```

A leaf tester returns a verdict and gives the reason with `ctx.fail`, which returns `False`. The
reason can be a function: it is called only when the difference is explained.

```python
class VersionEqualityTester(BaseEqualityTester[Version]):
    def objects_are_equal(self, actual, expected, ctx):
        return actual.number == expected.number or ctx.fail(
            lambda: f"versions differ: {actual.number} vs {expected.number}"
        )
```

**Migration of the v1.0 pre-release API (handlers and chain testers):**

| Before                                                             | After                                                                 |
| ------------------------------------------------------------------ | --------------------------------------------------------------------- |
| `BaseChainEqualityTester`, `HandlerEqualityTester`, `create_chain` | A `BaseEqualityTester` with one method `objects_are_equal(a, e, ctx)` |
| `BaseEqualityHandler`, `SameObjectHandler`, `SameTypeHandler`, ... | Removed: the engine checks the identity and the type                  |
| `config.registry.objects_are_equal(a, b, config)` (recursion)      | Return the child pair `(a, b, path part)`                             |
| `report_difference(config, message, path=...)`                     | `return ctx.fail(reason, *path)`                                      |
| `check_recursion_depth`, `track_comparison`, `HandlerCycleError`   | Removed: the engine owns the depth and the cycles                     |
| `tester.equal(other)`                                              | `tester == other` (same type and same attributes)                     |
| `EqualityConfig(atol=..., rtol=...)`, `config.reports`             | `EqualityConfig(tolerance=Tolerance(...))`; the config is frozen      |
| `Engine(registry, config)`                                         | `Engine(config, explaining=False)`                                    |
| `PandasDataFrameEqualityTester`, `PolarsSeriesEqualityTester`, ... | `TableEqualityTester(adapter)`, registered by the default registry    |
| `from coola.equality.handler import ...`                           | Private (`coola.equality._helpers`); use `coola.equality`             |
| `MaxDepthExceededError` is a `RecursionError`                      | A plain `Exception`; there is no `RecursionError` from the engine     |

#### Type-Specific Classes

**Before (v0.11):**

```python
from coola.equality.comparators import (
    TorchTensorComparator,
    NumpyArrayComparator,
    MappingEqualityComparator,
    SequenceEqualityComparator,
)
```

**After (v1.0):**

```python
from coola.equality import (
    TorchTensorEqualityTester,
    NumpyArrayEqualityTester,
    MappingEqualityTester,
    SequenceEqualityTester,
)
```

**Migration:** Replace `Comparator` with `EqualityTester` in class names. The pandas, polars and
PyArrow testers are one `TableEqualityTester` with an adapter per library.

#### Changes of the results

The rules are the same for every container and every library. A comparison can change in these
cases:

- `bool` and the members of an `enum.Enum` are labels: the tolerance never applies to them (also
  `IntEnum`, `numpy.bool_` and pandas booleans).
- An integer difference is computed in integers: `2**62` and `2**62 + 1` are different with
  `atol=0.5` in an array, as they are in a list.
- `float16`, `bfloat16` and `float32` are compared in double precision (no wrong `True` at the edge
  of the range).
- `MappingProxyType` and `array.array` are compared like a mapping and a sequence.
- pandas, polars and PyArrow numbers follow the tolerance; the nested and `object` cells are
  compared by the library (`equals`), without tolerance. The tolerance does not apply to an index.
- A table (data frame, series, index, Arrow table) is one leaf of the explanation: the path stops
  at the table and the reason names the first column that differs.
- `OrderedDict` keeps its order, a `dict` does not. A cycle is equal. A nesting deeper than
  `max_depth` raises `MaxDepthExceededError`.

### 4. Explaining a Difference: `show_difference` Removed

`show_difference=True` (a log message) is replaced by two functions that explain the first
difference only, on demand: `compare` returns a `ComparisonResult` and `assert_objects_equal` /
`assert_objects_allclose` raise an `AssertionError`. `objects_are_equal` and `objects_are_allclose`
format nothing.

**Before:**

```python
import logging

logging.basicConfig(level=logging.INFO)
objects_are_equal(actual, expected, show_difference=True)
```

**After:**

```pycon
>>> from coola.equality import compare, assert_objects_equal
>>> result = compare({"a": [1, 2, 3]}, {"a": [1, 2, 4]})
>>> result.equal
False
>>> result.path
('a', 2)
>>> print(result.format_message())
objects are not equal at actual['a'][2]
numbers are different:
  actual   : 3
  expected : 4
>>> assert_objects_equal({"a": 1}, {"a": 2})
Traceback (most recent call last):
    ...
AssertionError: objects are not equal at actual['a']
numbers are different:
  actual   : 1
  expected : 2

```

`compare(actual, expected, rtol=0.0, atol=0.0, ...)` takes the same keywords as
`objects_are_allclose` (exact by default). `ComparisonResult` has `equal`, `path` (keys, positions,
`AttributeName`, `Element`) and `reason`, and no `actual` / `expected` fields.

### 5. Formatters Removed

The `coola.formatters` module has been removed. Use `coola.summary` for text representation instead.

**Before (v0.11):**

```python
from coola.formatters import Formatter, DefaultFormatter

formatter = DefaultFormatter()
formatted_output = formatter.format(obj)
```

**After (v1.0):**

```python
from coola.summary import summarize

summary_output = summarize(obj)
```

**Migration:**

- Replace formatter calls with `summarize()` function
- The `summarize()` function provides similar text representation functionality
- If you need custom formatting logic, implement a custom `BaseSummarizer`

### 6. Summarization

The summarization module has been renamed from `summarizers` to `summary`.

**Before (v0.11):**

```python
from coola import summary

summary_text = summary(value, max_depth=2)
```

**After (v1.0):**

```python
from coola.summary import summarize

summary_text = summarize(value, max_depth=2)
```

**Changes:**

- Module renamed: `coola.summarizers` → `coola.summary`
- Function renamed: `summary()` → `summarize()`
- Top-level import removed: use `from coola.summary import summarize`

### 7. Reduction

The reduction module has been renamed from `reduction` to `reducer`.

**Before (v0.11):**

```python
from coola.reduction import Reduction

# Use the global reducer
Reduction.reducer  # Access current reducer
```

**After (v1.0):**

```python
from coola.reducer import auto_reducer, NativeReducer, NumpyReducer

# Create reducer instances directly
reducer = auto_reducer()  # Automatically selects best available backend
# Or use specific reducers:
# reducer = NativeReducer()    # Pure Python
# reducer = NumpyReducer()     # NumPy backend
# reducer = TorchReducer()     # PyTorch backend
```

**Migration:**

- Update module name: `coola.reduction` → `coola.reducer`
- The `Reduction` class pattern has been replaced with direct reducer instances
- Use `auto_reducer()` for automatic backend selection

**Changes of the reducers:**

- `auto_reducer()` returns `NumpyReducer` if NumPy is installed, else `NativeReducer`. It no longer
  returns `TorchReducer` when PyTorch is installed (it is slower on a list and slow to import):
  create `TorchReducer()` explicitly for tensors that live on a device.
- `BaseBasicReducer` is removed. Subclass `BaseReducer`, which now owns the checks (empty input,
  iterator, options, shape) and calls the private computations `_max`, `_mean`, `_median`, `_min`,
  `_quantile`, `_std` and `_sort`. `_is_empty` and `_check_values` are removed; implement
  `_prepare` to convert or validate the input if needed.
- `sort(values, *, descending=False)`: `descending` is keyword-only.
- `EmptySequenceError` is a `ValueError`.
- The input is a sequence of real numbers (`list`, `tuple`, `range`) or a one-dimensional array /
  tensor for the backend. An iterator, a set, a `str`, an n-d or 0-d array, a complex number, an
  integer beyond 64 bits (NumPy and PyTorch) or a `Decimal` raise `TypeError` or `ValueError`
  with the same text in every backend (they used to return a value or raise `AttributeError`,
  `RuntimeError`, ...). `NativeReducer` rejects arrays and tensors: use `NumpyReducer` or
  `TorchReducer`.
- `quantile` raises `ValueError` for a quantile outside `[0, 1]` (or `NaN`) in the three backends,
  before the values are read.
- `NativeReducer.mean` uses `statistics.fmean`: it is much faster and the last bit of a float mean
  can differ.

### 8. New Features in v1.0

Several new modules have been added in v1.0:

- **`coola.iterator`**: DFS/BFS traversal of nested structures
- **`coola.recursive`**: Recursive processing utilities
- **`coola.registry`**: Generic registry implementations

These are new additions and don't require migration from v0.11.

## Common Migration Patterns

### Pattern 1: Simple Equality Checks

**Before:**

```python
from coola import objects_are_equal
import torch

result = objects_are_equal({"a": torch.tensor([1, 2, 3])}, {"a": torch.tensor([1, 2, 3])})
```

**After:**

```python
from coola.equality import objects_are_equal
import torch

result = objects_are_equal({"a": torch.tensor([1, 2, 3])}, {"a": torch.tensor([1, 2, 3])})
```

### Pattern 2: Tolerance-Based Comparison

**Before:**

```python
from coola import objects_are_allclose
import numpy as np

result = objects_are_allclose(np.array([1.0, 2.0]), np.array([1.0001, 2.0001]), atol=1e-3)
```

**After:**

```python
from coola.equality import objects_are_allclose
import numpy as np

result = objects_are_allclose(np.array([1.0, 2.0]), np.array([1.0001, 2.0001]), atol=1e-3)
```

### Pattern 3: Summarization

**Before:**

```python
from coola import summary

text = summary([1, 2, 3, {"key": "value"}], max_depth=2)
print(text)
```

**After:**

```python
from coola.summary import summarize

text = summarize([1, 2, 3, {"key": "value"}], max_depth=2)
print(text)
```

### Pattern 4: Custom Comparators/Testers

See [Custom Equality Testers](#custom-equality-testers) above: a tester has one method
`objects_are_equal(actual, expected, ctx)` that returns a verdict or the child pairs.

## Testing Your Migration

After migrating your code, ensure everything works correctly:

1. **Update imports**: Run your code to check for import errors
2. **Run tests**: Ensure all existing tests pass
3. **Check functionality**: Verify equality checks produce the same results
4. **Review custom code**: If you have custom comparators/testers, review and test thoroughly
